## 6. 网络与清理状态机

实线说明业务因果；`D` 标记合理推导的异常/防重约束。loading 外观为 U03，任何采用的在途 UI 必须遵守 D10。

```mermaid
stateDiagram-v2
  [*] --> Preparing: 进入确认页 / 读订单缓存并 GET-Q
  Preparing --> ReadyNoAddress: 缓存就绪且 GET-Q 成功 / 无地址
  Preparing --> ReadyAddress: 缓存就绪且 GET-Q 成功 / 有地址
  Preparing --> LoadFailed: GET-Q 失败
  LoadFailed --> Preparing: 既有重试 / GET-Q
  ReadyNoAddress --> ReadyNoAddress: 点提交 / 底部Toast，POST-O=0
  ReadyNoAddress --> SelectingAddress: 点地址 / 进入列表
  ReadyAddress --> SelectingAddress: 点地址 / 进入列表
  SelectingAddress --> ReadyAddress: 返回已选地址 / 更新当前地址
  SelectingAddress --> PriorReady: 取消或无结果 / 保留原选择 D03
  PriorReady --> ReadyNoAddress: 原来无地址
  PriorReady --> ReadyAddress: 原来有地址
  ReadyAddress --> Submitting: 点提交 / 校验并快照、POST-O一次
  Submitting --> Submitting: 重复点击 / 无新增POST-O D05
  Submitting --> ReadyAddress: 网络/业务/数据失败 / 结束在途、不清车不跳 D04
  Submitting --> Created: 成功响应有效 / 得到id及realPrice
  Created --> PayPage: 自动导航 / orderId=id，price=realPrice
  Created --> Cleaning: 购物车来源 / 后台异步DB-C
  Cleaning --> CleanDone: 所购逐项清理结束
  Cleaning --> CleanFailed: 本地异常 / 补偿策略U05
```

`PayPage` 与 `Cleaning` 是由同一 `Created` 派生的并行效果，不是二选一。非购物车来源直接没有 Cleaning 分支；本图的创建成功判断不包含“支付完成”。页面离开/应用被杀的在途处理见 U04/U06，不由该示意图暗定。
