# 创建订单功能（表单校验/提交下单/跳转支付）

## 场景一

### 场景概述

用户在确认订单页面完成所有信息确认，点击"提交订单"按钮后，系统校验收货地址是否已填写，若验证通过则调用接口创建订单，成功后自动跳转到支付页面。

### 操作步骤与预期结果

1. 用户在确认订单页面完成商品浏览和备注填写，确认收货地址、商品信息均正确。
2. 用户点击底部"提交订单"按钮，系统检测到收货地址已填写，开始提交订单请求。
3. 系统将商品列表、收货地址ID、订单备注和所选优惠券ID等参数打包发送给服务器。
4. 服务器创建订单成功，返回订单信息（含订单ID和实付金额）。
5. 系统根据返回的订单ID和实付金额，自动跳转到支付页面。

## 场景二

### 场景概述

用户提交订单时未选择收货地址，系统弹出错误提示，阻止订单提交；用户返回补充地址后可正常下单。

### 操作步骤与预期结果

1. 用户进入确认订单页面，但页面上方的收货地址区域为空（未设置默认地址）。
2. 用户直接点击底部"提交订单"按钮，系统检测到收货地址缺失。
3. 页面底部弹出Toast错误提示："请选择收货地址"，订单提交操作被中止。
4. 用户点击地址区域跳转到地址列表页，选择或新增一个收货地址后返回确认订单页。
5. 用户再次点击"提交订单"，系统正常创建订单并跳转到支付页面。

## 场景三

### 场景概述

用户从购物车下单并成功创建订单后，系统自动将本次已购买的商品从购物车中删除，保持购物车数据的准确性。

### 操作步骤与预期结果

1. 用户从购物车页面选择商品并点击结算，进入确认订单页面。
2. 用户提交订单，服务器成功创建订单并返回订单ID。
3. 系统在后台异步执行清理操作：逐一移除本次订单中已购买的购物车商品。
4. 若某商品在购物车中的所有规格均已购买，则直接删除该商品整条购物车记录。
5. 若只有部分规格被购买，则仅删除对应规格，其余规格仍保留在购物车中。
