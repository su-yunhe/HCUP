# 搜索结果支持手动分页加载

## 场景一

### 场景概述

当搜索接口返回的第一页结果仍有后续数据时，歌曲列表在首批结果末尾显示明确的“点击加载更多”入口。

### 操作步骤与预期结果

1. 用户在搜索页输入关键字并提交搜索。
2. 页面显示第一批歌曲，原有歌曲卡片均可正常浏览。
3. 用户滚动到第一批结果末尾。
4. 列表底部显示“点击加载更多”，而不是自动发起不可控的重复请求。

## 场景二

### 场景概述

用户点击“点击加载更多”后，应用按当前偏移量请求下一页，并把新歌曲追加到已有列表后面。

### 操作步骤与预期结果

1. 用户在第一批搜索结果末尾点击“点击加载更多”。
2. 页面请求下一页搜索结果并短暂显示加载状态。
3. 下一页歌曲追加到原列表末尾，第一页内容不被替换。
4. 用户可以继续浏览新追加的歌曲。

## 场景三

### 场景概述

当接口表明全部搜索结果已经加载完成时，列表显示“没有更多了~”，并移除旧的加载更多入口。

### 操作步骤与预期结果

1. 用户加载搜索结果的最后一页。
2. 新结果追加完成后，应用更新 hasMore 状态。
3. 用户滚动到列表底部看到“没有更多了~”。
4. 底部不再显示“点击加载更多”，避免重复请求相同页面。
