## 2. 原文、状态与共同前置

需求的决定性原文为：

- `spec/requirement.md:7`：用户点击「从云端恢复」打开第一层确认弹窗后，如果点击「取消」，弹窗必须关闭，页面回到 WebDAV 设置操作区。
- `spec/requirement.md:20`：取消恢复操作后，「从云端恢复」按钮仍须可用。用户应能再次点击该按钮，打开恢复确认弹窗。
- `spec/requirement.md:33`：用户取消恢复后再次打开确认弹窗，只要没有明确点击「继续」，应用仍不得向 WebDAV 服务端发送请求。
- `spec/requirement.md:40`：在用户未点击「继续」前，测试环境不应观察到任何 WebDAV 请求。

第一层 D1 位于任何恢复 WebDAV 调用之前；下载及预览后的 D2 是另一层。三个精确动作文本是「从云端恢复」「取消」「继续」。D1 标题、说明、Toast、状态字段和窗口实现方式没有原文约束。

本轮共同测试约定沿用 `spec/acceptance.md:76-80`、`:224-234`：

- P0：通过既有入口进入 WebDAV 操作区，初始化完成，无在途请求/重试；使用独立可计数端点，自动同步关闭且持久化完成，不点击其他联网操作；首次恢复点击前建立请求计数基点。
- P1：P0 加已保存并满足既有校验的测试配置。有效配置用于证明 gate 真的阻断了本可发出的请求，不是 Spec 新增前置。核心明文测试采用 P1，空/空白另测。
- P2：P1 加已完成一次「打开 D1 → 取消 → D1 关闭」。
- N0：在没有明确点击本轮 D1「继续」的连续窗口内，所有 WebDAV 请求累计增量为 0；统计所有方法、路径、状态码、预检、重试和重定向。窗口覆盖首次打开、取消、停留、重开及异步排队完成，不能取消后清零或只统计 GET。
- D1 等待、取消及关闭不能调用真实恢复任务；纯弹窗模态状态与真实请求 busy 分开。取消后的入口可用性按 UI 状态完成点与实际重开验证，不规定人为的毫秒阈值。

## 5. 方案和验证须更新/失效的项目

1. **入口与调用图须更新。** 基线 `SettingsSyncSection.ets:164-165` 在入口直接进入 busy 包装，`:199-200` 下载；`WebDavSyncManager.ets:471-484` 包含本地校验、预检和下载。实施方案必须让 D1 的明确继续先于这整条恢复任务；仅改 D2 的取消分支不能解决 A9—A14。取消、非按钮关闭、重复事件均不能调用这条链或复用先前授权。
2. **状态图须更新。** 应描述 Ready→Confirm→Ready/Authorized 的分层，取消完成即可重开；确认本身不进入真实请求 loading。D1 单实例和重复点击保护应在方案中明确，避免晚到关闭回调破坏下一轮状态。具体字段名由方案角色决定。
3. **D1/D2 选择器混用失效。** 把 `⚠️ 恢复确认`/`确认恢复` 当成第一层的旧定位逻辑必须废弃。`spec/acceptance.md:53-70` 的 S0—S11 是建议契约，实施者可统一等价稳定定位；原生系统弹窗应实测窗口/标题/精确按钮限定办法，不能声称给 buttons 数据随意加 `.id()` 就有组件 id。最终映射写入方案/验证记录即可，本报告不改批准 acceptance。
4. **只查 Toast/颜色/GET 的测试不足。** A4—A8 分别断言 D1 消失、操作区可交互、原文入口可见、enabled、实际重开。A9—A14 使用连续外部请求日志，所有方法和失败状态码均计数；单纯 mock 导入、看无 loading、空地址或断网日志不能替代网络证据。服务端不可见的 DNS/连接失败需结合客户端尝试证据。
5. **核心用例与派生证据须齐全。** 主序列至少按三个 Spec 场景实际执行，并覆盖多轮与快速未授权动作；以非空哨兵数据或导入边界调用计数支持 A16；用确认态与请求调用链、取消后实际重开支持 A17/A18；用重复取消无残层支持 A19。继续对照放在独立窗口，不污染取消窗口的 N0。
6. **边界和回归需分级记录。** 空/空白配置按 U1 测；已支持关闭方式按 U2 测；返回/重进/重启按 U4 记录为回归；继续后 D2/服务流程按 U5 记录为回归。没有云端数据不允许在 D1 前发 HEAD 探测；Spec 没有分页，最后一页不适用。不得把这些实现选择扩写为新正式需求，也不得据未测结果宣称通过。
7. **批准分析记录保持历史有效。** `spec/baseline-notes.md` 的基线失败证据不因修复变为失效历史；其中「D1 尚缺失」是基线结论，不再用来描述修复后现状。本轮应新增最终源码映射、构建/安装/运行及逐 A 项证据，不能覆盖历史日志或沿用基线 A1 通过来代替修复后回归。

建议下一步由主 Agent 将以上边界交给方案角色，确认 D1 授权门槛及可观测性，再由编码角色实施，独立验证角色按 A1—A19 与分级回归取证。需求角色本轮产物仅为本文件；本轮没有新增超范围正式需求或用户必答问题。
