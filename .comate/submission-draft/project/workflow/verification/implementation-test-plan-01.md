## 3. 测量和数据隔离

- 本地真实 HTTP mock 服务监听专用 loopback 端口，通过本题专用 `hdc rport tcp:<port> tcp:<port>` 到设备；记录原有转发，结束仅移除本题新增转发和服务进程。
- mock 对未知 HTTP 方法同样记账，既不只统计 GET，也不按成功响应过滤；不保存 Authorization。由服务端连续追加请求日志计数，测试阶段不清空历史，只打基点。
- 前置使用独立 endpoint/账号/根目录，关闭自动同步并保存、等待空闲；不复用旧服务凭据。主禁发窗口内不点测试连接、立即同步、备份等其它联网动作。
- 主窗口起点在首次恢复点击前，连续覆盖首次打开、停留、取消、取消后停留、再次打开、循环取消、快速连点和末尾等待；每一步累计增量必须为 0。主场景永不点击 `继续`。另设超过 120 秒的取消后等待用于延迟请求回归，仍不把有限时间当产品允许的阈值。
- 网络正控独立开窗：有效配置下明确点击当前 D1 的 `继续`，要求 mock 收到真实请求并观察既有结果/空闲复位。它只证明授权链路与计数可用，不将恢复成功升级为 Spec 明文。
- 无云端数据由 mock empty/404 模式预置，不通过未授权 HEAD 探查；云端有数据回归可用本应用向本地 mock 备份所得密文，再经本题原加解密恢复到 D2 并点其原生 `取消`。
- 本地数据先记录状态。空数据场景不得删除不明既有数据；若需空态只在主 Agent 批准的本题可恢复干净设备状态执行，否则该分支 `blocked`。A16 必须有非空哨兵的可复现前后数据证据，优先通过既有 UI 创建测试词/词书并导出或读取可观察快照；无法安全取得快照时标 `blocked`，不以空数据或零请求偷换通过。
