## 6. 真实 WebDAV 状态机与动作请求表

### 6.1 明文约束与推导模型

下图描述验收模型，节点不是强制实现变量或类。实线 E 受明文约束；标 D 的终结恢复来自推导；U 代表未决策略。

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Configured: 进入并填写可访问配置 A01/A02
    Configured --> BackupRunning: 点击立即备份 A03/A07/A11
    state BackupRunning {
        [*] --> Preparing
        Preparing --> RequestInFlight: 发出真实WebDAV请求 A13/A14
        RequestInFlight --> MoreWork: 响应后流程仍未结束
        MoreWork --> RequestInFlight: 如有后续真实请求
        MoreWork --> Finished: 实际操作完成
        RequestInFlight --> Finished: 最终响应使操作终结
    }
    BackupRunning --> Success: 真实操作成功结束 D01
    BackupRunning --> Failed: 失败结果或异常终结 D02/D03
    Success --> Idle: 清理busy/进行中UI D01
    Failed --> Idle: finally等效清理 D02/D03
    BackupRunning --> LeftPage: 返回或关闭 U06/U07
    LeftPage --> Configured: 重进时恢复策略待确认 U07
    BackupRunning --> ProcessStopped: 强制退出或重启 U08
    ProcessStopped --> Configured: 重启后策略待确认 U08
```

绑定规则：A05/A06 要求备份运行时存在可见 `LoadingProgress`；A09/A10 要求同期间进行中文字可见；A16 要求同一忙碌可见流程发送真实请求。Preparing 包括导出、加密或请求准备，**不要求从点击开始的每一瞬间都已有请求**。用网络延迟制造一个可观察的运行窗口；不能用计时器做一个没有真实备份的假加载。

Spec 未要求某种 HTTP 方法、固定请求数、固定文件名、服务端必须成功、百分比进度、固定显示时长或上传后恢复路由。它要求真实备份操作中的真实 WebDAV 请求；仅伪造 console、请求无关 URL 或只更改 UI 都不能当成满足。对于“仅预检而无上传是否足够”，保留 U02，不擅自扩大明文。

### 6.2 基线真实调用链与超时分叉（BASELINE_CODE）

```mermaid
stateDiagram-v2
    [*] --> UIIdle
    UIIdle --> UIBusy: 点击备份，guard通过 C4
    UIBusy --> ManagerCheck: busy=true，写正在备份到云端，等待50ms
    ManagerCheck --> FinalUI: 配置缺失或已有SYNCING，返回失败 C6/C7
    ManagerCheck --> Preflight: manager置SYNCING
    Preflight --> Export: 缓存或目录可达/准备完成 C8
    Preflight --> FinalUI: 预检返回失败，manager=ERROR
    Preflight --> OuterCatch: 预检抛异常，未进manager的try
    Export --> EncryptTask: 导出成功 C7
    Export --> ManagerFinally: 导出失败或try内异常
    EncryptTask --> ParentCheck: 加密成功 C9
    EncryptTask --> ManagerFinally: 加密失败
    ParentCheck --> BackupPUT: 可能HEAD及PUT .keep C10
    BackupPUT --> ManagerFinally: HTTP结果或任务失败 C9
    ManagerFinally --> FinalUI: manager=IDLE，返回结果 C7
    OuterCatch --> FinalUI: UI包装catch处理 C4
    FinalUI --> UIIdle: 写结果，UI finally busy=false C4
    UIBusy --> UITimedOut: 外层Promise.race达到120000ms C4
    UITimedOut --> UIIdle: UI写异常并finally解除busy
    UITimedOut --> IOStillPossible: 无取消底层Promise的代码
    IOStillPossible --> LateCompletion: 原操作以后才完成，可能有远端副作用
```

读取此图时必须区分两个时钟：**UI 等待 Promise 已拒绝**，不证明**底层 I/O 已取消**。外层超时后 spinner 是否必须继续显示、能否发起下一轮、晚到成功如何呈现，Spec 未作规定，见 U06；此处只列基线风险。C4 UI finally 不能证明 manager 也始终复位；C7 预检抛错发生在 manager try/finally 外。不得在分析阶段修复，也不得把这些附加风险一律标成官方功能失败。

基线网络序列：`webdavBackup()` → `backupToCloudInBackground()` → 可选预检 → 本地导出 → 加密任务 → `WebDavClient.put(backupFilePath, ...)` → 真实 `http.request`。PUT 前还可能检查父目录。预检缓存/根目录分支可能无请求；成功上传路径的 PUT 是现有实现事实，**不是把 PUT、HEAD、DELETE 或某个请求数提升为 SPEC_EXPLICIT**。当前按钮不调用 `WebDavBackupManager.backupToCloud()`，不能把那个方法的后续 HEAD 误写进本按钮的必经链路。

## 9. 后续验证证据与复审失效条件

推荐最小正例证据包（尚未执行）：有效测试端点与设备可达性记录；本次点击 t0；UI 树中 T5 的实际 `LoadingProgress` 类型及可见性；同窗 T6 进行中文字；服务端本次真实请求 URL/method/开始及结束；放行后 UI 终态。UI 与服务端采样需对齐，最好让服务端保持真实请求 pending，分别在等待期间两次检查 UI，避免仅靠截图或仅靠 console。

Hypium 可断言页面/组件/文字/状态，但单凭 Hypium UI 不证明服务器收到请求；网络项需要测试服务端日志或等价真实网络证据。未具备服务端/设备可达性时应标“网络未验证”，不能标通过或凭此否定明文要求。Spec 没有写应用账号登录步骤；正常网络正例需要设备可访问且有权限的 WebDAV 服务端、有效配置和可导出的本地数据库。首次引导/其它入口前置以基线实操记录为准，本文未运行验证。
