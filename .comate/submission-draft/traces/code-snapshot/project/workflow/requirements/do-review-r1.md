## 4. 首页内容和网络边界的明确判断

### 首页必须建立的内容

1. **明文**：有首页内容、顶部优惠券“领取”入口和真实可纵向滚动的内容；在目标设备上可让同一顶部入口滚出视口，点击已选首页后又回到顶部并重现（`spec/requirement.md:12,47,51–53`；A3、A23–A25）。底栏应始终可操作，纵滚不改变当前首页标签（A34）。
2. **明文边界**：“限时精选”“推荐商品”由“例如”引入（`spec/requirement.md:47`），不是强制的商品结构、数目、排序、接口或交易任务。实现可用合理的本地展示内容形成可滚动首页；采用这些示例标题也不自动新增商品业务义务。
3. **验收底线**：不能只放一个不够滚动的占位标题，不能把“领取”固定在底栏或屏幕上，不能用隐藏/删除该入口伪造滚出，不能用另一个同名按钮证明回顶。必须观察原顶部入口从视口外恢复到视口内（`spec/acceptance.md:175–189`）。
4. **不扩展交易**：Spec 没有点击“领取”的步骤，也没规定券库存、领取成功、登录、购买、商品详情、分页或领券请求。入口文案与位置用于回顶可见性观察，不要求实现领取提交（`spec/acceptance.md:66`；`spec/baseline-notes.md:163`）。

### 网络的适用性

- **需求判定**：本题没有必须调用的 API、参数、次数、服务器响应、loading 文案或重试按钮要求（`spec/requirement.md:1–54`；`spec/acceptance.md:296–301`）。选择本地内容、本地真实 Lottie 资源，不接入首页网络请求，在满足全部本地交互时符合本题范围。
- **已有代码边界**：批准基线记录有首页实体、仓库及 GET `page/home` 定义，但未接入当前 HomePage；这些定义不是本题必须联网的证据，真实服务与首页响应未验证（`spec/baseline-notes.md:129–131,164`）。已有账户存储或登录拦截也不构成四标签必须先登录的前置（同文 `:137,162`）。本次引用批准源码审计结果，不重复读取上游或运行服务。
- **若方案主动使用网络**：请求状态必须与导航/动画/回顶分开；其成功、空数据、失败要按实际结果恢复，不能把回顶变成“刷新成功才返回顶部”，不能让无数据免验场景四。具体请求业务 UI 只有另有批准依据才能变成硬性验收（A36–A37；`spec/acceptance.md:218–219,298–301`）。
- **测试标记**：最终未发生相关网络请求时，网络故障注入写“不适用：本题无相关请求”，并记录依据；不能声称真实接口或网络失败恢复已通过。若确有请求则依据该实际实现验证，不能杜撰一个导航 API。
