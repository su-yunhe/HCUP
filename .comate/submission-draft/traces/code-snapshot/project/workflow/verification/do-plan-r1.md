## 真实 Lottie 动态证据方案

### 播放、颜色及取样

- 源码/资源审计只证明真实本地 Lottie 的接入、资源 `fr/ip/op`、一次播放与 reset 的来源；不单独证明设备已播放。保留实际依赖/播放器调用与资源哈希，禁止将符号位移或 CSS/ArkUI 普通动画冒充 Lottie。
- 冻结后先在本题设备上探测可用的屏幕录制/截图能力并记录命令、吞吐和帧时间戳。采集在触发前开始，覆盖动作、真实播放和结束后的静止窗口。优先设备连续录屏；若不可用则采用连续截图并用实际采集时刻核验覆盖。采集速度错过动画时标 `blocked`，补充合适采集，不把末帧当作播放。
- 保存原始全屏视频/PNG，不只留裁剪或统计。每帧绑定 monotonic 时间、设备、动作序号、同时间段 UI 树、图标 bounds、ROI 裁剪与哈希。图像检查只裁图标内绘制区域，排除标签文字、系统时间、触摸圈及页面位移。
- 必须出现播放期间内部形状/位置等真实随时间变化；选中灰变黑的一次差异不足以证明动画。采样可产生多个时间点/不同形态，并与实际 Lottie 帧回调相互印证；不预设固定毫秒或隐藏素材，采样窗口依据实现资源时长和实际设备节奏确定。
- 颜色在落定后读取可用 UI 属性，并以图标/文字截图的非抗锯齿内部像素交叉验证；区分分类图标黑、其他三图标灰及首页文字黑。容差由原始图像及环境噪声确定并登记，不用随意“深色”阈值代替黑色，不把实现素材色误当额外 Spec RGB 要求。

### 第一帧、一次播放和无新增播放

- 首页离开后的 `frame=0` 必须是 Lottie 引擎真实复位（若有回调/状态接口），加资源第一帧参照和多个间隔截图的静止证据；只变灰、节点消失或自己写的 count 不能证明 A19/A39。若暂时无法取得可信第一帧参照，相关项保留 `blocked` 并反馈观测缺口。
- 主 Agent 转达设计侧已核实 `@ohos/lottie 2.0.33` 声明提供 `currentFrame/isPaused` 与 `DOMLoaded/enterFrame/drawnFrame/complete`，可与图标 ROI 联合取证；这是设计交接信息，实际安装包接口、回调时间线及最终 ID 仍须冻结后实测，不在准备阶段冒称已验证。
- A16：在正常入口冷启动前启动采集，初始化后没有用户点击，观察首页实际播放。权限遮挡及采集晚到分别记录，必要时重测；不能把被系统覆盖时的假定播放当作用户可见播放。
- A20：先完整执行初始化→离开→复位，再点未选首页，观察一次从初始帧经动态帧到结束的序列，结束后至少再覆盖一个资源播放周期，排除重复循环/重复回调新增播放。增量只相对于本次动作，不写死整个进程已有计数。
- A28/A31/A32：先等首页静止，下滚/顶部时点击已选首页，保存点击前后图标 ROI 与引擎事件，确认无新起始及无新动态周期，内容可纵向回顶。另在原动画尚在播放时重击，允许既有周期继续，必须结合起始事件/帧进程确认未从头重播。
- A27：采集 PAGER 和活动页的连续状态/截图，确认始终是同一首页；首页内容的纵向滚动允许，不能因画面变化一概判定切页。
